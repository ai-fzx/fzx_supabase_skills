# Supabase 建表规范

## Overview

Supabase 基于 PostgreSQL，建表需遵循 PG 生态最佳实践。核心原则：**snake_case 命名、UUID 主键、TIMESTAMPTZ 时间、TEXT 字符串、RLS 必开、外键必索引**。

## 命名规范

| 规范 | 说明 |
|------|------|
| `snake_case` | 表名、列名统一小写+下划线，禁驼峰（PG 自动转小写，驼峰需双引号） |
| 表名复数 | `users`、`posts`、`orders` |
| 列名单数 | `email`、`created_at`、`status` |
| 禁止空格 | 用下划线分隔 |

```sql
-- ✅
CREATE TABLE users (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  email TEXT UNIQUE,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- ❌
CREATE TABLE Users (Email VARCHAR(255), CreatedAt TIMESTAMP);
```

## 字段类型选择

| 场景 | 推荐 | 不推荐 | 原因 |
|------|------|--------|------|
| 字符串 | `TEXT` | `VARCHAR(n)` | PG 中性能相同，TEXT 无长度限制 |
| 时间戳 | `TIMESTAMPTZ` | `TIMESTAMP` | 带时区，跨地区用户不受影响 |
| 主键 | `UUID` | `SERIAL` | UUID 全局唯一，分布式安全 |
| 数字主键 | `BIGINT GENERATED BY DEFAULT AS IDENTITY` | `SERIAL` | identity 符合 SQL 标准 |

## 主键规范

- **每张表必须有主键**
- 优先 `UUID` + `DEFAULT gen_random_uuid()`
- 需要数字 ID 时用 `BIGINT GENERATED BY DEFAULT AS IDENTITY`

```sql
-- UUID 主键（推荐）
id UUID PRIMARY KEY DEFAULT gen_random_uuid()

-- 数字主键（备选）
id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
```

## 关系设计

### 一对一

外键加 `UNIQUE` 约束：

```sql
CREATE TABLE profiles (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID UNIQUE REFERENCES users(id) ON DELETE CASCADE,
  bio TEXT
);
```

### 一对多

外键放在「多」的那一方：

```sql
CREATE TABLE books (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  author_id UUID REFERENCES authors(id) ON DELETE CASCADE,
  title TEXT NOT NULL
);
```

### 多对多

中间表 + 联合主键：

```sql
CREATE TABLE enrollments (
  student_id UUID REFERENCES students(id) ON DELETE CASCADE,
  course_id UUID REFERENCES courses(id) ON DELETE CASCADE,
  PRIMARY KEY (student_id, course_id)
);
```

## RLS 行级安全规范

> **强制：建表后立即启用 RLS**，否则 anon key 可访问全部数据！

```sql
ALTER TABLE [table_name] ENABLE ROW LEVEL SECURITY;
```

### 常用策略模板

**用户只能操作自己的数据：**

```sql
CREATE POLICY "Users manage own data"
ON posts FOR ALL
TO authenticated
USING (user_id = auth.uid());
```

**公开/私有混合数据：**

```sql
-- 所有人可看已发布，作者可看草稿
CREATE POLICY "Published posts visible to all"
ON posts FOR SELECT
TO public
USING (status = 'published');

CREATE POLICY "Authors can see own drafts"
ON posts FOR SELECT
TO authenticated
USING (user_id = auth.uid());
```

### RLS 性能优化

- **RLS 策略引用的列必须加索引**（10 万行表查询可快 10 倍）
- 避免用 `FOR ALL`，分开写 `SELECT`/`INSERT`/`UPDATE`/`DELETE` 策略（PG 可按操作优化索引）
- 重复子查询用 `SECURITY DEFINER` 函数封装

```sql
-- 索引
CREATE INDEX idx_posts_user_id ON posts(user_id);

-- 封装子查询
CREATE OR REPLACE FUNCTION user_teams()
RETURNS SETOF UUID
LANGUAGE SQL SECURITY DEFINER STABLE
AS $$ SELECT team_id FROM team_members WHERE user_id = auth.uid(); $$;
```

## Schema 隔离

敏感数据放独立 schema，不暴露在 public API：

```sql
CREATE SCHEMA private;

CREATE TABLE private.salaries (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  salary BIGINT NOT NULL,
  actor_id BIGINT NOT NULL REFERENCES public.actors
);
```

## 索引规范

| 场景 | 规范 |
|------|------|
| 外键列 | **必须加索引** |
| RLS 策略引用列 | **必须加索引** |
| 高频查询字段 | 加索引 |
| 低基数列（如 gender） | 不建议加索引 |

```sql
CREATE INDEX idx_books_author_id ON books(author_id);
```

## 时间字段规范

```sql
created_at TIMESTAMPTZ DEFAULT NOW(),
updated_at TIMESTAMPTZ DEFAULT NOW()

-- 自动更新 updated_at 的 trigger
CREATE OR REPLACE FUNCTION update_updated_at()
RETURNS TRIGGER AS $$
BEGIN
  NEW.updated_at = NOW();
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER update_posts_updated_at
BEFORE UPDATE ON posts
FOR EACH ROW EXECUTE FUNCTION update_updated_at();
```

## 完整建表模板

```sql
-- 创建表
CREATE TABLE posts (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  title TEXT NOT NULL,
  content TEXT,
  status TEXT NOT NULL DEFAULT 'draft',
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- 启用 RLS
ALTER TABLE posts ENABLE ROW LEVEL SECURITY;

-- RLS 策略
CREATE POLICY "Users can manage own posts"
ON posts FOR ALL
TO authenticated
USING (user_id = auth.uid());

-- 索引
CREATE INDEX idx_posts_user_id ON posts(user_id);
CREATE INDEX idx_posts_status ON posts(status);

-- 自动更新 updated_at
CREATE TRIGGER update_posts_updated_at
BEFORE UPDATE ON posts
FOR EACH ROW EXECUTE FUNCTION update_updated_at();
```

## 速查表

| 规范项 | 推荐做法 |
|--------|---------|
| 命名 | `snake_case`，表名复数 |
| 主键 | `UUID` + `DEFAULT gen_random_uuid()` |
| 字符串 | `TEXT`（不用 `VARCHAR`) |
| 时间戳 | `TIMESTAMPTZ`（不用 `TIMESTAMP`) |
| 建表后 | 立即 `ENABLE ROW LEVEL SECURITY` |
| 外键 | 必须加索引 + 定义 `ON DELETE` |
| RLS 策略列 | 必须加索引 |
| 敏感数据 | 放 `private` schema |

## Common Mistakes

| 错误 | 正确做法 |
|------|---------|
| 用 `VARCHAR(255)` | 用 `TEXT`，除非需要明确限制长度 |
| 用 `TIMESTAMP` | 用 `TIMESTAMPTZ`，避免时区问题 |
| 用 `SERIAL` 做主键 | 用 `UUID` 或 `IDENTITY`，SERIAL 在分布式场景有冲突风险 |
| 忘记启用 RLS | 建表后立即 `ALTER TABLE ... ENABLE ROW LEVEL SECURITY` |
| 外键不加索引 | 外键列必须加索引，否则 JOIN 和 RLS 性能极差 |
| 用 `FOR ALL` 策略 | 分开写各操作策略，PG 可优化索引使用 |
| 敏感表放 `public` schema | 放 `private` schema，不暴露 API |
